# Evidence-driven Debugging

## 目标

找到正确状态第一次变成错误状态的边界，在拥有该规则的层实施最小修复，并用回归证据证明问题被捕获。Skill 不保存项目当前方法、字段、架构实例、领域不变量或验证命令副本。

## 范围

诊断阶段默认只读。用户要求修复时，只修改已确认根因直接涉及的生产代码、回归测试以及 `docs/log.md`；实际完成设备或模拟器验收时，可按 `AGENTS.md` 新增对应 `test_note/**` 记录。其他文件遵循适用单层或跨层 Skill 的范围。

不得通过弱化断言、吞异常、任意延时、无限重试、跳过测试、返回假成功或大范围重构使症状暂时消失。保护用户已有修改，不执行破坏性 Git 或数据操作。

## 强制项目导航

开始诊断前，按顺序读取：

1. 生效的 `AGENTS.md`；
2. `docs/architecture/overview.md`；
3. 规范化期望行为、实际行为、复现条件、影响、范围和完成定义；
4. `docs/index.md`，据此定位相关 Domain、Accepted ADR、Active Plan、Machine Contract、当前状态、Open Issue 和验证入口；
5. 复现路径上的直接代码、配置、日志、测试和最近相关 diff。

Source of Truth 和冲突裁决遵循 `AGENTS.md`。具体领域规则、跨层方法、存储状态、版本和发布能力只从当前权威资料读取；README 与历史记录仅作 index 允许的兜底证据。

## 证据纪律

- 始终区分已确认事实、推断和未知项。
- 崩溃行、异常栈顶、错误提示和最终 UI 只是观察点，不自动等于根因。
- 优先运行修改最少、信息增益最高的实验；一次实验只改变一个因果变量。
- 根因必须连接：触发条件 → 第一个错误状态 → 下游传播 → 可见症状。
- 无法复现时可以继续静态调查，但结论只能标为领先假设，并说明缺少的运行时证据。
- 所有日志、payload、数据库样本和转储都要避免泄露凭据、密钥或用户隐私。

## 工作流

### 1. 建立可复现案例

- 优先运行用户提供的失败测试/命令，其次使用最接近的现有测试，再考虑最小临时 reproducer。
- 记录输入、环境、构建类型、时间/时区、设备/ABI、频率、关键日志和退出结果中与问题相关的部分。
- 对间歇性问题控制时间、随机性、线程、调用顺序、数据量和生命周期，避免用 sleep 掩盖竞态。

### 2. 追踪第一个错误边界

- 从输入到输出沿实际调用链逐层比较状态、类型、身份、版本、错误和副作用。
- 边界名称和不变量从当前 Contract/Domain/ADR 获取，不在 Skill 中假设固定链路。
- 对每一层标记输入是否正确、输出是否正确、是否已执行、是否发生副作用以及证据来源。

### 3. 建立并区分假设

维护少量能解释现象的候选，每个候选记录支持/反对证据、为真/为假的预测、最低成本区分实验和置信度。

不要因为代码“看起来可疑”就修改。只有实验排除了合理替代解释，并找到第一个错误边界后，才宣称根因确认。

### 4. 修复与回归

- 在拥有规则的最窄层修复根因，不在调用方复制补丁或改变未涉及语义。
- 先添加能因正确原因失败的回归覆盖，再实施最小修复；无法先写测试时说明原因。
- 测试覆盖原始复现、关键边界/失败条件和不应改变的相邻行为。
- 只在同一根因、因果关系明确且可验证时修复附近同类实例，否则作为剩余风险报告。

## 停止条件

暂停受影响修复，当：

- 用户期望与当前 Machine Contract/Domain/ADR/Active Plan 冲突，且会改变修复方向；
- 根因位于用户禁止修改的层；
- 必须取得设备、生产数据、外部服务或破坏性实验才能继续；
- 无法区分本次问题与用户已有修改；
- 迁移、兼容性或数据恢复方案存在不可接受的不确定性。

停止不等于结束调查：先完成仍可安全执行的复现、静态追踪和区分实验，再报告最小缺失证据。

## 验证纪律

通过 `docs/index.md` 定位当前验证指南，并按风险逐层扩大：

1. 回归测试和原始复现；
2. 根因所属模块的定向测试/静态检查；
3. 受影响模块的构建与回归；
4. 涉及 Contract、JNI、Storage、系统能力或多层组合时执行当前 smoke/integration/设备验证；
5. 性能、并发或恢复缺陷使用可重复数据集与故障注入，不用一次运行证明稳定。

C++ 变更必须使用项目规定的 build-after-test 目标。当前 `AGENTS.md`、验收标准和验证指南要求但未运行、失败、未覆盖或只能静态确认的部分必须标为未验证；不自行扩大设备/ABI 矩阵。

## 交付

报告症状、根因或领先假设、触发条件、第一个错误边界、因果链、修改、回归证据、实际验证、影响范围和剩余风险。被阻塞时给出下一项信息增益最高的实验。始终追加 `docs/log.md`。
