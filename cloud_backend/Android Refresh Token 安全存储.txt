  ### 特有约束
  - 必须使用 EncryptedSharedPreferences 或 Android Keystore 实现，禁止使用普通 SharedPreferences
  - Refresh Token 在任何情况下都不得写入 Android 日志（Log.d / Log.i / Log.e 等）
  - 不得通过 BroadcastReceiver 或 ContentProvider 暴露 Refresh Token
  - 不得在未加密的备份（android:allowBackup）中包含 Refresh Token
  - 应用数据被清除时必须自动删除 Refresh Token
  - Flutter 通过 MethodChannel 请求读取时，返回明文 Token；但方法调用结束后 Flutter 必须立即释放引用
  - 删除操作必须原子执行，不能出现已删除但存储失败的中间状态
  - 所有 4 个 MethodChannel 方法（store/read/delete/exists）必须在主线程之外执行（使用协程或后台线程）
  - 如果 Android 版本低于 M（API 23），需提供降级方案但必须明确标记为"不安全"
  - 不实现任何认证业务逻辑，只做安全的 Token 存储和读取

  # Android Refresh Token Secure Storage

  ## 上下文
  - Contract: `contracts/method_channels.yaml` 中 auth.refresh_token.* 方法
  - 完整流程：`docs/完整流程.md` 第三~四章

  ## 实现目标
  在 Android/Kotlin 层实现 4 个 MethodChannel 方法：

  1. `auth.refresh_token.store` — 保存 Refresh Token 到 Android Keystore
  2. `auth.refresh_token.read` — 从安全存储中读取 Refresh Token
  3. `auth.refresh_token.delete` — 删除 Refresh Token
  4. `auth.refresh_token.exists` — 检查 Refresh Token 是否存在

  ## 安全要求
  - 使用 EncryptedSharedPreferences 或 Android Keystore
  - 不保存到普通 SharedPreferences
  - 不输出到日志
  - App 数据清除时自动删除
  - 用户退出时主动删除
