# ExcellentCalendarAPP 用户认证与个人信息模块开发流程

## 一、开发目标

完成 ExcellentCalendarAPP 的用户认证与个人信息模块，使用户能够完成以下完整业务流程：

1. 注册账号。
2. 验证注册邮箱。
3. 使用邮箱和密码登录。
4. 自动恢复登录状态。
5. 查看个人信息。
6. 修改昵称、用户名、头像等个人信息。
7. 修改登录邮箱。
8. 修改密码。
9. 忘记密码后通过邮箱重置密码。
10. 主动退出登录。
11. 登录凭证过期后自动刷新。
12. Refresh Token 失效后自动回到登录页面。

本任务只设计并实现业务流程，不在本阶段重点设计数据库表或详细数据结构。

# 二、模块职责划分

## 2.1 Flutter 负责的内容

登录、注册和个人信息相关业务主要在 Flutter 中完成。

Flutter 负责：

* 登录页面。
* 注册页面。
* 邮箱验证页面。
* 忘记密码页面。
* 重置密码页面。
* 个人信息页面。
* 编辑个人信息页面。
* 修改头像页面。
* 账号安全页面。
* 修改密码页面。
* 修改邮箱页面。
* 网络请求。
* 表单校验。
* 登录状态管理。
* Access Token 管理。
* 接口错误转换。
* 页面跳转。
* 加载、成功和失败状态。
* 请求失败后的重试。
* Access Token 过期后的刷新流程。
* 用户信息的内存缓存和普通本地缓存。

Flutter 可以直接请求后端认证接口，不需要让登录、注册等请求经过 Kotlin 或 C++。

## 2.2 Android Native 负责的内容

Android 只承担必须依赖原生安全能力的部分。

Android 负责：

* Refresh Token 的安全保存。
* Refresh Token 的安全读取。
* Refresh Token 的安全删除。
* 使用 Android Keystore 或其支持的加密存储保护 Refresh Token。
* 向 Flutter 返回 Refresh Token 是否存在。
* App 数据被清除或用户退出时删除 Refresh Token。

Android 不负责：

* 登录业务判断。
* 注册流程。
* 用户资料修改。
* 登录页面状态。
* Access Token 的日常管理。
* 解析后端业务错误。
* 直接控制 Flutter 页面跳转。

Flutter 和 Android 之间只为 Refresh Token 安全存储建立少量 MethodChannel 调用。

## 2.3 Backend 负责的内容

Backend 负责所有真实认证和账号数据：

* 创建账号。
* 校验邮箱和密码。
* 校验用户名是否可用。
* 发送邮箱验证码或验证链接。
* 验证邮箱。
* 签发 Access Token。
* 签发 Refresh Token。
* 刷新登录凭证。
* 保存用户资料。
* 保存头像地址。
* 修改邮箱。
* 修改密码。
* 发送密码重置邮件。
* 验证密码重置凭证。
* 注销 Refresh Token。
* 管理用户在不同设备上的登录会话。
* 对登录、注册和验证码接口进行频率限制。

## 2.4 C++ Core 的职责边界

本模块中的认证流程不进入 C++ Core。

C++ Core 不负责：

* 保存密码。
* 校验密码。
* 登录和注册。
* Token 生成。
* Token 刷新。
* 邮箱验证码。
* 用户认证网络请求。
* Refresh Token 保存。

C++ Core 后续只需要在业务数据同步时接收已经确认的用户身份，不参与身份认证本身。

# 三、Token 管理方案

## 3.1 Access Token

Access Token 由 Flutter 管理。

推荐规则：

1. 登录成功后，将 Access Token 保存到 Flutter 的认证状态管理器中。
2. Access Token 主要保存在内存中。
3. 所有需要登录的请求，由 Flutter 网络请求层自动添加 Access Token。
4. 页面不能直接读取或拼接 Access Token。
5. 页面不能自行决定什么时候刷新 Token。
6. Access Token 失效后，由统一网络层处理。
7. 用户退出登录后，立即清除内存中的 Access Token。
8. 不建议将 Access Token 保存到普通 SharedPreferences、普通文件或 SQLite。

如果应用进程被杀死，Flutter 不依赖旧 Access Token 恢复会话，而是使用 Android 中保存的 Refresh Token 请求新的 Access Token。

## 3.2 Refresh Token

Refresh Token 由 Android Native 安全保存。

Flutter 只能通过 MethodChannel 执行以下操作：

```text
保存 Refresh Token
读取 Refresh Token
删除 Refresh Token
检查 Refresh Token 是否存在
```

流程要求：

* Flutter 不把 Refresh Token 保存到 Dart 普通缓存。
* Flutter 不在日志中输出 Refresh Token。
* Android 不把 Refresh Token 保存到普通 SharedPreferences。
* 用户退出后必须删除 Refresh Token。
* 刷新凭证失败后必须删除 Refresh Token。
* 密码重置导致会话失效时必须删除 Refresh Token。
* Android 返回 Refresh Token 后，Flutter仅在刷新请求期间短暂使用，不长期保留在状态对象中。

## 3.3 Token 刷新

统一刷新流程：

```text
业务请求
    ↓
后端返回 Access Token 已过期
    ↓
Flutter 网络层暂停当前失败请求
    ↓
通过 MethodChannel 从 Android 读取 Refresh Token
    ↓
Flutter 请求后端刷新接口
    ↓
刷新成功
    ├── 更新 Flutter 内存中的 Access Token
    ├── 将新 Refresh Token 保存到 Android
    └── 重试原业务请求
    ↓
刷新失败
    ├── 清除 Flutter Access Token
    ├── 删除 Android Refresh Token
    ├── 清除当前用户状态
    └── 跳转登录页面
```

必须保证：

* 多个请求同时遇到 Token 过期时，只允许执行一次刷新请求。
* 其他请求等待同一个刷新结果。
* 刷新成功后统一重试。
* 刷新失败后统一退出登录。
* 不允许每个请求分别刷新一次。

# 四、应用启动流程

应用启动后不能直接决定进入主页或登录页，必须先经过统一的认证检查页面。

完整流程：

```text
App 启动
    ↓
显示启动页或认证检查页
    ↓
检查 Flutter 内存中是否存在有效 Access Token
    ↓
通常首次启动时不存在
    ↓
通过 MethodChannel 查询 Android 是否保存 Refresh Token
```

## 4.1 不存在 Refresh Token

```text
不存在 Refresh Token
    ↓
认证状态设置为未登录
    ↓
进入登录页面
```

## 4.2 存在 Refresh Token

```text
存在 Refresh Token
    ↓
Flutter 从 Android 临时读取 Refresh Token
    ↓
调用后端刷新接口
```

刷新成功：

```text
获得新的 Access Token 和 Refresh Token
    ↓
Access Token 放入 Flutter 内存
    ↓
新 Refresh Token 写回 Android
    ↓
请求当前用户资料
    ↓
进入应用主页
```

刷新失败：

```text
删除 Android 中的 Refresh Token
    ↓
清除 Flutter 登录状态
    ↓
进入登录页面
```

## 4.3 启动异常

如果网络暂时不可用：

* 不应进入一个无法使用的半登录状态。
* 默认显示登录恢复失败页面。
* 提供重新尝试按钮。
* 可以允许用户进入本地离线模式，但必须清楚标识当前账号尚未完成认证恢复。
* 离线模式是否开启应由项目后续统一决定，本任务默认不自动进入离线模式。

# 五、登录流程

## 5.1 页面内容

登录页面包括：

* 账号或邮箱输入框。
* 密码输入框。
* 密码显示与隐藏按钮。
* 登录按钮。
* 忘记密码入口。
* 注册入口。

## 5.2 前端校验

点击登录前，Flutter 完成基础校验：

* 邮箱不能为空。
* 邮箱格式基本正确。
* 密码不能为空。
* 登录请求进行中时禁止重复点击。

客户端校验只用于改善用户体验，不能替代服务端校验。

## 5.3 登录请求流程

```text
用户填写邮箱和密码
    ↓
Flutter 校验表单
    ↓
登录按钮进入加载状态
    ↓
Flutter 调用后端登录接口
```

登录成功：

```text
后端返回用户信息、Access Token 和 Refresh Token
    ↓
Access Token 保存到 Flutter 内存
    ↓
Refresh Token 通过 MethodChannel 保存到 Android
    ↓
更新全局登录状态
    ↓
缓存基本用户信息
    ↓
进入应用主页
```

## 5.4 登录失败处理

需要分别处理：

* 密码错误。
* 邮箱尚未验证。
* 账号已被禁用。
* 请求过于频繁。
* 网络不可用。
* 请求超时。
* 服务器异常。

邮箱未验证时：

```text
登录接口返回邮箱未验证
    ↓
Flutter 保存当前邮箱
    ↓
跳转邮箱验证页面
    ↓
允许用户重新发送验证邮件
```

登录失败时：

* 保留邮箱输入。
* 停止按钮加载状态。
* 显示可理解的错误提示。
* 不直接展示服务端堆栈或原始异常。
* 不清空整个页面。
* 不保存密码。

# 六、注册流程

## 6.1 页面内容

注册页面包括：

* 邮箱。
* 用户名。
* 昵称。
* 密码。
* 确认密码。
* 密码显示与隐藏。
* 同意用户协议。
* 注册按钮。
* 返回登录入口。

## 6.2 客户端校验

Flutter 负责基础校验：

* 所有必填项已经填写。
* 邮箱格式正确。
* 用户名格式正确。
* 昵称长度合理。
* 密码满足最低要求。
* 两次密码一致。
* 用户已经同意用户协议。（具体用户协议内容暂时留空，占位即可）
* 请求期间禁止重复提交。

## 6.3 注册流程

```text
用户填写注册信息
    ↓
Flutter 完成本地校验
    ↓
Flutter 调用后端注册接口
    ↓
Backend 检查邮箱和用户名
```

如果邮箱或用户名已存在：

```text
Backend 返回对应错误
    ↓
Flutter 将错误显示在相应输入框附近
    ↓
保留用户已经填写的其他内容
```

如果注册信息有效：

```text
Backend 创建待验证账号
    ↓
Backend 向邮箱发送验证码或验证链接
    ↓
Flutter 跳转邮箱验证页面
```

注册阶段默认不直接进入主页，必须先完成邮箱验证。

# 七、邮箱验证流程

## 7.1 页面内容

邮箱验证页面包括：

* 当前待验证邮箱。
* 验证码输入区域，或者验证链接状态提示。
* 确认验证按钮。
* 重新发送按钮。
* 重新发送倒计时。
* 返回登录入口。
* 修改邮箱入口。

邮箱在页面中建议脱敏显示。

## 7.2 验证码方式

```text
用户输入验证码
    ↓
Flutter 完成非空和长度校验
    ↓
调用后端邮箱验证接口
```

验证成功：

```text
Backend 将邮箱标记为已验证
    ↓
Backend 签发 Access Token 和 Refresh Token
    ↓
Access Token 保存到 Flutter 内存
    ↓
Refresh Token 保存到 Android
    ↓
请求当前用户资料
    ↓
进入应用主页
```

验证失败时区分：

* 验证码错误。
* 验证码已过期。
* 验证码已经使用。
* 请求次数过多。

## 7.3 重新发送

```text
用户点击重新发送
    ↓
Flutter 检查倒计时是否结束
    ↓
调用后端重新发送接口
    ↓
发送成功后重新开始倒计时
```

请求过程中禁止重复发送。

新验证码发送成功后，旧验证码应由后端决定失效。

# 八、忘记密码流程

## 8.1 页面内容

忘记密码页面包括：

* 邮箱输入框。
* 发送重置邮件按钮。
* 返回登录入口。

## 8.2 请求流程

```text
用户输入邮箱
    ↓
Flutter 校验邮箱格式
    ↓
调用后端密码重置申请接口
```

无论邮箱是否真实存在，页面统一显示：

```text
如果该邮箱已经注册，系统会向该邮箱发送密码重置邮件。
```

这样可以避免通过接口判断某个邮箱是否注册。

## 8.3 请求结果

请求成功后：

* 显示邮件已发送提示。
* 显示检查垃圾邮件的提示。
* 提供重新发送入口。
* 提供返回登录入口。
* 对重新发送进行倒计时限制。

# 九、密码重置流程

密码重置可以通过应用深度链接或用户手动输入验证码进入。

## 9.1 页面内容

* 新密码。
* 确认新密码。
* 显示与隐藏密码。
* 确认重置按钮。

## 9.2 重置流程

```text
应用接收到密码重置链接或验证码
    ↓
Flutter 提取重置凭证
    ↓
用户输入新密码
    ↓
Flutter 校验密码和确认密码
    ↓
调用后端密码重置接口
```

重置成功：

```text
Backend 更新密码
    ↓
Backend 使旧登录会话失效
    ↓
Flutter 清除 Access Token
    ↓
Flutter 请求 Android 删除 Refresh Token
    ↓
跳转登录页面
    ↓
提示用户使用新密码重新登录
```

重置失败时处理：

* 链接无效。
* 验证码错误。
* 凭证已过期。
* 凭证已经使用。
* 新密码不符合要求。
* 请求次数过多。

# 十、个人信息主页流程

个人信息主页展示：

* 用户头像。
* 昵称。
* 用户名。
* 登录邮箱。
* 邮箱验证状态。

* 时区。
* 编辑资料入口。
* 修改头像入口。

## 10.2 加载流程

```text
进入个人信息页面
    ↓
先读取 Flutter 本地缓存
    ↓
如果存在缓存，立即展示
    ↓
同时调用后端获取最新用户资料
```

请求成功：

```text
使用服务端资料更新页面

更新 Flutter 用户状态
```

* 显示“信息可能不是最新”的提示。

# 十一、修改个人资料流程

## 11.1 可修改内容

普通资料编辑页面负责：

* 昵称（初始昵称可以用数字和字母随机生成）。
* 用户名。
* 语言。
* 时区。
* 其他非安全型个人资料。

以下内容不在普通编辑页修改：

* 登录邮箱。
* 密码。
* Refresh Token。
* 账号状态。

## 11.2 编辑流程

```text
用户进入编辑页面
    ↓
页面使用当前资料初始化
    ↓
用户修改内容
    ↓
Flutter 判断是否发生变化
```

如果没有发生变化：

* 保存按钮保持禁用。

发生变化后：

```text
用户点击保存
    ↓
Flutter 完成基础校验
    ↓
保存按钮进入加载状态
    ↓
Flutter 调用后端更新资料接口
```

更新成功：

```text
Backend 返回更新后的完整资料
    ↓
Flutter 更新全局用户状态
    ↓
更新本地缓存
    ↓
返回个人信息主页
    ↓
显示修改成功提示
```

更新失败：

* 保留用户当前输入。
* 不覆盖为旧值。
* 停止加载状态。
* 显示具体错误。
* 允许再次提交。

本任务中的“实时上传修改”定义为：

```text
用户点击保存后立即上传，
服务器确认成功后再更新本地正式状态。
```

不要求每输入一个字符就发送一次请求。

# 十二、头像修改流程

## 12.1 入口

用户在个人信息页面点击头像或“修改头像”（初始头像可以使用一张图片作为默认头像）。

## 12.2 图片选择

```text
Flutter 调用图片选择能力
    ↓
用户从系统相册选择图片
    ↓
Flutter 获得图片
```

如果用户取消：

* 关闭选择流程。
* 不修改当前头像。
* 不显示错误。

## 12.3 图片处理

选择成功后：

* 检查文件是否可以读取。
* 检查文件大小。
* 检查图片格式。
* 允许用户裁剪。
* 将头像裁剪为正方形。
* 对图片进行合理压缩。
* 显示上传前预览。

## 12.4 上传流程

```text
用户确认头像
    ↓
Flutter 显示上传进度
    ↓
Flutter 上传头像到后端或对象存储
    ↓
Backend 保存头像并更新用户资料
    ↓
Backend 返回新的头像信息
```

上传成功：

```text
更新 Flutter 用户状态
    ↓
清理旧头像缓存
    ↓
显示新头像
    ↓
更新本地用户缓存
```

上传失败：

* 保留旧头像。
* 不更新用户状态。
* 显示失败原因。
* 提供重新上传按钮。

## 12.5 删除头像

```text
用户选择删除头像
    ↓
弹出确认对话框
    ↓
用户确认
    ↓
Flutter 调用后端删除头像接口
    ↓
成功后恢复默认头像
```

# 十三、修改密码流程

## 13.1 页面内容

* 当前密码。
* 新密码。
* 确认新密码。
* 显示与隐藏密码。
* 确认修改按钮。

## 13.2 修改流程

```text
用户输入当前密码和新密码
    ↓
Flutter 完成基础校验
    ↓
调用后端修改密码接口
```

后端负责：

* 验证当前密码。
* 验证新密码强度。
* 判断新旧密码是否相同。
* 更新密码。
* 使其他设备的 Refresh Token 失效。

修改成功后：

```text
Backend 返回成功
    ↓
Flutter 清除当前 Access Token
    ↓
删除 Android 中的旧 Refresh Token
```

推荐策略：

```text
Backend 同时返回当前设备的新 Token
    ↓
Flutter 保存新 Access Token
    ↓
Android 保存新 Refresh Token
    ↓
当前设备继续登录
```

其他设备退出登录。

如果后端不返回新会话，则修改成功后跳转登录页重新登录。

修改失败时处理：

* 当前密码错误。
* 新密码不符合要求。
* 新密码和旧密码相同。
* 登录会话已经失效。
* 网络异常。

---

# 十四、修改邮箱流程

修改邮箱属于高风险操作，不能在普通资料编辑页面直接保存。

## 14.1 页面内容

* 当前邮箱，只读。
* 新邮箱。
* 当前密码。
* 发送验证邮件按钮。

## 14.2 修改流程

```text
用户输入新邮箱和当前密码
    ↓
Flutter 完成基础校验
    ↓
调用后端申请修改邮箱接口
```

后端负责：

* 验证当前密码。
* 检查新邮箱是否已经被使用。
* 创建临时邮箱修改申请。
* 向新邮箱发送验证码或验证链接。

随后：

```text
Flutter 跳转邮箱验证页面
    ↓
用户完成新邮箱验证
    ↓
Backend 正式替换登录邮箱
```

修改成功：

```text
Flutter 重新获取当前用户资料
    ↓
更新页面和本地缓存
    ↓
根据后端策略刷新 Token
```

在新邮箱验证成功前：

* 原邮箱仍然有效。
* 原邮箱仍可以用于登录。
* 页面不能提前显示新邮箱已经生效。

---

# 十五、退出登录流程

## 15.1 用户主动退出

```text
用户点击退出登录
    ↓
显示确认对话框
    ↓
用户确认退出
    ↓
Flutter 调用后端退出接口
```

无论后端退出接口是否因为网络问题失败，本地都必须继续完成退出：

```text
清除 Flutter Access Token
    ↓
清除 Flutter 用户状态
    ↓
清除普通用户缓存中的敏感会话信息
    ↓
通过 MethodChannel 删除 Android Refresh Token
    ↓
清空页面导航栈
    ↓
进入登录页面
```

退出后按返回键不能回到已登录页面。

## 15.2 所有设备退出

账号安全页面可以提供“退出所有设备”。

```text
用户点击退出所有设备
    ↓
进行二次确认
    ↓
调用后端注销全部 Refresh Token
    ↓
清除当前设备 Access Token
    ↓
删除 Android Refresh Token
    ↓
进入登录页面
```

# 十六、统一网络请求流程

Flutter 应建立统一认证网络层，而不是每个页面单独处理 Token。

普通请求流程：

```text
页面
    ↓
Controller / Application Service
    ↓
Repository 或 API Client
    ↓
认证请求拦截器
    ↓
自动添加 Access Token
    ↓
发送后端请求
```

返回成功：

```text
解析响应
    ↓
更新 Controller 状态
    ↓
更新页面
```

返回 Access Token 过期：

```text
触发统一 Token 刷新
    ↓
刷新成功后重试一次原请求
```

原请求重试后仍然认证失败：

* 不再次无限刷新。
* 清除登录状态。
* 返回登录页。

网络层必须避免：

* 无限刷新循环。
* 无限请求重试。
* 每个页面各写一套 Token 刷新代码。
* 多个并发刷新请求。
* 直接把后端原始错误显示给用户。

# 十七、页面状态要求

每个涉及网络请求的页面至少需要处理：

* 初始状态。
* 输入状态。
* 提交中状态。
* 成功状态。
* 表单错误状态。
* 网络错误状态。
* 服务端业务错误状态。
* 登录失效状态。

提交中必须：

* 禁用重复提交。
* 显示加载反馈。
* 避免用户连续点击产生多个账号或多封邮件。
* 页面销毁后不再更新页面状态。

不得使用多个互相冲突的布尔变量表示状态，例如：

```text
isLoading = true
isSuccess = true
hasError = true
```

应使用明确且互斥的流程状态。

# 十九、异常边界

## 19.1 网络中断

* 停止加载状态。
* 显示网络错误。
* 保留用户输入。
* 提供重试操作。
* 不把请求标记为成功。

## 19.2 请求超时

* 允许用户重新提交。
* 可能造成重复写入的操作，需要后端支持幂等或重复判断。
* 注册、验证码发送、头像上传尤其要避免重复执行。

## 19.3 App 进入后台

* 普通表单内容应尽量保留。
* Access Token 可以继续存在于进程内存。
* 进程被系统杀死后，通过 Android Refresh Token 恢复会话。
* 上传任务是否继续执行，由实际上传实现决定。

## 19.4 Access Token 被服务端撤销

```text
业务请求返回认证失败
    ↓
尝试刷新
    ↓
刷新也失败
    ↓
删除 Refresh Token
    ↓
退出到登录页
```

## 19.5 用户资料更新冲突

当用户在多个设备修改资料时：

* 以服务端最终返回的资料为准。
* 客户端提交成功后必须使用服务端响应更新状态。
* 客户端不能只在本地修改后假定后端一致。

# 二十、安全要求

必须遵守：

1. 密码不得写入日志。
2. Access Token 不得写入日志。
3. Refresh Token 不得写入日志。
4. Refresh Token 不得保存在 Flutter 普通存储。
5. Refresh Token 必须由 Android 安全保存。
6. Access Token 默认只保存在 Flutter 内存。
7. 用户退出时删除所有本地凭证。
8. 所有认证请求必须使用 HTTPS。
9. 忘记密码接口不能暴露邮箱是否存在。
10. 邮箱验证码必须有有效期和发送频率限制。
11. 密码重置后旧 Refresh Token 必须失效。
12. 修改密码后至少使其他设备会话失效。
13. 头像上传必须检查实际文件类型和文件大小。
14. 页面错误提示不能展示服务端堆栈。
15. Flutter 不应在 Widget 中直接操作 Token。

# 二十二、验收流程

完成后必须至少能够完整执行以下流程。

## 流程一：注册

```text
打开 App
→ 进入注册页面
→ 填写账号信息
→ 注册成功
→ 收到验证邮件
→ 完成邮箱验证
→ 自动进入应用主页
```

## 流程二：登录恢复

```text
登录成功
→ 关闭 App
→ 再次打开 App
→ Android 读取 Refresh Token
→ Flutter 刷新 Access Token
→ 自动进入主页
```

## 流程三：资料修改

```text
进入个人信息页面
→ 修改昵称
→ 保存
→ 返回个人信息页面
→ 显示最新昵称
→ 重启 App 后昵称仍然正确
```

## 流程四：头像修改

```text
选择头像
→ 裁剪
→ 上传
→ 显示新头像
→ 重启 App
→ 仍然显示新头像
```

## 流程五：修改密码

```text
输入当前密码和新密码
→ 修改成功
→ 其他设备会话失效
→ 当前设备继续登录或重新登录
→ 新密码能够正常登录
```

## 流程六：忘记密码

```text
退出登录
→ 点击忘记密码
→ 输入邮箱
→ 收到重置邮件
→ 设置新密码
→ 返回登录页
→ 使用新密码登录成功
```

## 流程七：Token 过期

```text
Access Token 过期
→ 业务请求返回认证失败
→ Flutter 自动读取 Android Refresh Token
→ 刷新成功
→ 自动重试原请求
→ 用户无感继续操作
```

## 流程八：Refresh Token 失效

```text
Refresh Token 失效
→ Flutter 刷新失败
→ 删除 Android Refresh Token
→ 清除 Flutter 登录状态
→ 自动进入登录页
```

## 流程九：退出登录

```text
点击退出
→ 清除 Access Token
→ 删除 Refresh Token
→ 清空用户状态
→ 返回登录页
→ 无法通过返回键进入主页
```
