# 日历-01：月周分类视图与三类数据聚合开发计划

Status: Active / Requirements Frozen / Specialist Split / Contract Pending

确认日期：2026-08-31

## 1. 计划定位

本计划把底部“日历”占位 Tab 建设为 Android 优先、本地优先的月/周分类日历，统一展示选中日期的：

- Event 与重复 Event occurrence；
- Habit 当地日期状态；
- Anniversary 当地日期 occurrence。

本计划只实现分类视图。顶部时间线按钮和更多设置按钮保留，但点击分别提示“时间线视图暂未开放”和“日历设置暂未开放”。

可行性判定：`SPECIALIST_SPLIT`。

原因：需求同时新增聚合 Contract、C++/SQLite 只读查询投影、Kotlin/JNI/MethodChannel 接线、Dart Gateway/Application 状态和完整 Flutter 页面，并消费三个独立业务模块。它可实现，但不是一次小型跨层补丁；必须按 Contract/数据、C++/Storage、Kotlin/JNI、Flutter、最终集成和独立 Review 分轨交付。

## 3. 已冻结的产品需求

### 3.1 顶部与日期导航

- 标题使用中文年月，例如“2026年8月”。
- 首次进入默认周视图；只持久化周/月偏好，不持久化冷启动选中日期。
- 冷启动选中今天；切换底部 Tab 后保留选中日期、折叠状态和滚动位置。
- 星期标题使用“一 二 三 四 五 六 日”，星期一为一周第一天。
- 左右滑动切换周/月范围；水平滑动后选择相同星期或相同日号，月底不足时选择目标月最后一个合法日期。
- 周/月切换保持当前选中日期。
- 点击年月标题弹出年月选择面板，面板提供“今天”。
- 当前不在今天时，年月标题旁显示小型“今天”按钮。
- 月视图中的相邻月份日期使用弱化样式但可点击；点击后进入对应月份并选中该日。
- 选中日期使用品牌色实心圆；今天未选中时使用品牌色细圆环；相邻月份日期使用弱化文字。
- 日期状态不能只依赖颜色，Semantics 必须说明“今天”“已选中”和该日包含的类型。

### 3.2 视图按钮与折叠

- 顶部左侧功能按钮代表“分类/时间线”视图；V1 固定分类视图，点击时间线入口显示暂不支持提示。
- 中间按钮显式切换周视图和月视图，并与滚动折叠状态同步。
- 右侧更多按钮点击显示“日历设置暂未开放”。
- 月视图向上滚动时平滑折叠为包含选中日期的一周。
- 周视图在页面顶部下拉时先展开完整月视图；月视图完全展开后继续下拉才触发刷新。
- 禁止下拉展开和下拉刷新同时抢占同一次手势；需要明确阈值、动画中断和无动画系统设置下的行为。

### 3.3 日期圆点

- 每个日期最多显示三个固定顺序的小圆点：日程蓝、习惯绿、纪念日橙。
- Event 圆点表示至少存在一个会显示且未完成的 Event/occurrence；只有已完成 Event 时不显示 Event 圆点。
- Habit 在挑战有效区间内默认显示 Habit 圆点；当天状态为 done 后移除 Habit 圆点。partial、absent、upcoming、missed 和 skipped 仍显示。
- Anniversary occurrence 存在时显示 Anniversary 圆点。
- 圆点只表达类型是否存在，不表达条目数量；不得因分页只查看第一页而漏判。

### 3.4 分组卡片

- 分组顺序固定为“日程 / 习惯 / 纪念日”。
- 空分组隐藏；三类均为空时显示“这一天还没有安排”和新建引导。
- 每组首次最多返回 20 条；有更多时显示“加载更多”，每组独立分页。
- 条目 V1 只进入详情，不在日历页直接完成 Event、打卡 Habit 或修改 Anniversary。
- 从详情页返回时由详情路由返回变更结果；只有发生修改时刷新当前可见范围和选中日，未修改时保留缓存。

日程条目显示：

- 类型图标、标题；
- 全天或开始时间；
- 完成、跳过等可见状态；
- 是否存在活动提醒；
- 重复 occurrence 的稳定 identity。

日程排序：

1. 全天在前；
2. 未完成在前，已完成在后；
3. 同组按当地开始时间升序；
4. 标题和稳定 ID 作为最终稳定排序键。

已完成 Event 继续显示在“日程”卡片底部，标题弱化并使用删除线及“已完成”状态。

习惯条目显示：

- 习惯图标、标题；
- 当天状态；
- 数量型当天完成量/目标量和单位；
- 是否存在活动提醒。

习惯状态文案：

- 今天无 CheckIn：待完成；
- partial：显示当天数量进度；
- done：已完成；
- skipped：已跳过；
- 历史无活动 CheckIn：未完成；
- 未来计划日：未到日期；
- 挑战区间外：不返回、不显示。

习惯排序为：待处理/partial → done → skipped/missed/upcoming，再按提醒当地时间、创建时间和稳定 ID 排序；最终排序必须由 C++ 投影定义，Flutter 不重算领域状态。

纪念日条目显示：

- 纪念日图标、标题；
- 第 N 周年或一次性纪念日；
- 是否存在活动提醒；
- occurrence identity。

纪念日只在选中日期确实存在 occurrence 时显示，不混入未来 7 天或“最近纪念日”倒计时。排序按重要程度、标题和稳定 ID。

### 3.5 跨日与重复 Event

- 普通定时 Event 和 occurrence 只要与选中当地自然日有非空重叠，就在该日显示。
- 跨日 Event 在覆盖的每一天显示：首日显示开始时间，后续日期显示“进行中”或当天结束时间。
- 全天 Event/occurrence 使用本地 date-only 半开区间 `[start_date, end_date)`，覆盖区间内每一天。
- 重复 occurrence 正常状态显示；completed 显示在分组底部；skipped 灰色显示“已跳过”；cancelled 不显示。
- 点击重复条目必须携带 occurrence key 进入 Event 详情，不能退化为只打开系列。

### 3.6 新建入口

- 右下角“＋”打开底部选择面板：“新建日程 / 新建习惯 / 新建纪念日”。
- 新建 Event 和 Anniversary 预填当前选中日期。
- 新建 Habit 时，选中日期为今天或未来则预填该日；选中历史日期则使用今天。
- 保存成功后返回日历，保持目标日期并刷新可见范围与对应分组。
- 悬浮按钮不得遮挡月历、卡片、加载更多或底部导航。

### 3.7 加载、缓存与失败

- 首次进入显示骨架加载；有缓存时切换日期先显示缓存并后台刷新。
- 快速切换日期、范围或 Tab 时，旧请求不能覆盖新选择；Controller 使用 generation/request identity 防止 stale response。
- 分组分页独立记录 `loading/ready/error/hasMore/cursor`，重复点击“加载更多”不得并发提交。
- 刷新失败时保留最近一次成功内容并显示可重试提示；无缓存时才显示全页错误。
- 下拉刷新重新查询当前可见范围和选中日期三组第一页，成功后原子替换页面快照。
- 时区变化或系统日期跨日后，使范围与选中日缓存失效；冷启动仍回到新的今天。

### 3.8 视觉、主题与无障碍

- 参考截图只规定信息结构，不逐像素复制来源应用。
- 复用项目现有品牌色、Theme、Appearance、圆角、阴影、字体和四 Tab 底栏。
- 支持浅色/深色主题、360dp 常见小屏、系统 inset、200% 字体和系统“减少动画”。
- 文本截断必须保留可访问完整标签；所有图标按钮提供中文 tooltip 和 Semantics。

## 5. 数据边界与拟议 Contract

### 5.1 设计原则

Calendar View 是只读组合投影，不是新的领域实体，不建立独立可写表。所有事实继续属于：

- Event / Recurrence / EventOccurrenceState；
- Habit / HabitCheckIn；
- Anniversary / AnniversaryRecurrence；
- Reminder 只提供“是否存在活动提醒”等查询投影。

C++ 在同一 Calendar Core 读边界内完成重复展开、自然日重叠、Habit 日状态、稳定排序和日期圆点判定。Flutter 只维护可见范围、选中日期、页面缓存和展示状态。

### 5.2 建议的公开能力

Contract 负责人最终冻结名称；除非评审证明需要调整，建议新增：

1. `calendar.range_summary`
   - 输入：当地半开日期范围、IANA timezone；
   - 范围非空且最多 42 个自然日，覆盖完整六周月历；
   - 输出：请求区间内每天恰好一项、日期升序、无缺口；
   - 每天返回 `has_open_event`、`has_pending_habit`、`has_anniversary` 三个布尔投影；
   - 不返回条目数量或本地化文案。

2. `calendar.list_day_items`
   - 输入：选中当地日期、`section=event|habit|anniversary`、IANA timezone、opaque cursor、`page_size`；
   - V1 页面使用 `page_size=20`，Contract 最大值建议 100；
   - 输出：单一 section 的 typed item 列表、`has_more`、`next_cursor`；
   - cursor 绑定日期、时区、section、排序条件、最后排序键与数据 snapshot generation；
   - terminal page 必须 `next_cursor=null`，非终页必须提供 cursor。

Flutter 首次加载选中日期时并行请求三个 section；其中任一失败不得让旧异步响应覆盖新的选中日期。范围摘要必须独立于分组分页，不能通过第一页是否为空推导圆点。

### 5.3 建议的投影类型

- `CalendarRangeDaySummary`：date 和三个类型存在性布尔值。
- `CalendarEventItem`：event id、nullable occurrence key、title、all-day/time range、当地日展示标签所需原始字段、状态、活动提醒投影。
- `CalendarHabitItem`：habit id、title、daily status、nullable CheckIn/progress、目标数量与单位、活动提醒投影。
- `CalendarAnniversaryItem`：anniversary id、occurrence key/date、title、years elapsed、repeat 标记、重要程度、活动提醒投影。
- `CalendarDayItemPage`：section、items、has more、next cursor。

Contract 不携带“待完成”“进行中”“第 N 周年”等本地化字符串；这些由 Flutter 根据类型化字段格式化。

### 5.4 时间与区间语义

- 精确时间继续使用 UTC Instant；日期网格和 Habit/Anniversary 使用请求 IANA timezone 下的当地 date。
- 定时 Event 与当地日窗口做半开区间重叠判断，不把 date 转成 UTC 午夜后直接比较。
- 全天 Event 和 Anniversary 使用 date-only；不得改写为 UTC datetime。
- DST gap/fold、跨午夜、跨月、闰年、月末和设备时区变化必须由固定 clock/timezone 测试覆盖。

### 5.5 错误与版本

Contract 负责人应复用公共错误体系并冻结至少以下语义：

- range 为空、反向或超过 42 天；
- 非法 date、timezone、section 或 page size；
- cursor malformed、query mismatch 或 snapshot expired；
- 下层 malformed data / contract version 不受支持；
- SQLite 查询、重复展开或统计溢出的真实失败。

所有公开/内部调用继续使用 `NativeResult<T>` 和当前 contract version 规则；不得用空成功结果吞掉协议错误。

## 6. 分层架构与职责

```text
CalendarPage / Calendar widgets
  → CalendarController / immutable UI state
  → CalendarGateway
  → MethodChannelCalendarAdapter + typed DTO
  → CalendarMethodHandler
  → JniCalendarBridge
  → C++ CalendarViewQueryService / Boundary
  → Event + Recurrence + Habit + Anniversary + Reminder repositories
  → SQLite read transaction / typed projection
```

| 层 | 责任 | 禁止 |
| --- | --- | --- |
| Flutter Presentation | 月周网格、手势、折叠、卡片、圆点、加载/错误、导航 | 解析 Map、展开 recurrence、重算 Habit 状态 |
| Flutter Application | 选中日、范围、缓存、分页、刷新、stale-response 防护 | 直接 MethodChannel、复制 C++ 排序 |
| Dart Gateway/DTO | 类型化请求响应、版本和错误映射 | 向页面暴露原始 JSON/PlatformException |
| Kotlin/JNI | 方法路由、线程与边界转换、NativeResult 透传 | 聚合业务规则或本地化文案 |
| C++ Query Service | 三类读取、重复展开、日期重叠、排序、圆点和 cursor | Android/Flutter 状态、可写第二真相源 |
| Repository/SQLite | 参数化查询、只读事务、必要索引与 snapshot generation | 页面逻辑、无证据新增缓存表 |

默认不新增持久化表或 Storage 版本。只有真实性能数据证明现有索引无法满足 42 天范围查询时，才另立 Storage/迁移决策，不在实现中临时加表。

## 7. Flutter 状态模型

页面状态至少表达：

- `selectedDate`、`visibleRange`、`viewMode=week|month`、`isCollapsed`；
- `rangeSummaryState=initialLoading|ready|refreshing|error`；
- Event/Habit/Anniversary 三个独立 `SectionState`；
- 每个 section 的 items、hasMore、cursor、isLoadingMore、error；
- 页面级最近成功快照和当前 request generation；
- 当前 timezone、今天和年月选择面板状态。

缓存建议：

- 范围摘要 key：`timezone + rangeStart + rangeEnd`；
- 分组第一页 key：`timezone + selectedDate + section`；
- cursor 页面只附着在对应第一页快照，不跨刷新复用；
- 详情发生修改、新建成功、时区变化或当地跨日时使关联 key 失效。
