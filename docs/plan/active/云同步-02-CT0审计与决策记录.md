## 7. 实验结果

13 个 JCS 等价边界向量覆盖排序/嵌套、UTF-16 键序、负零、指数、四舍五入、safe integer、控制字符、array/null、重复 key 和孤立 surrogate。期望 bytes/hash 固定在 `canonical_vectors.json`，不由被测 encoder 生成。

Windows picojson、Java Jackson、Dart json 的原始编码均有反例，不可直接复用为 JCS。Windows 现有 SHA-256 的 8 个独立 KAT（空串、abc、55/56/63/64/65 字节、百万 a）通过；这不替代生产提取、全输入审计和三 ABI 运行。Android 原始 encoder 探针三 ABI 编译通过，设备在执行期间断开，三 ABI runtime 均未取得通过证据。

SQLCipher Community 4.18.0 AAR 摘要与 Maven 上游 `.sha256` 一致；候选三 ABI 均导出当前 Storage 所需 sqlite3 API 与 key API，并成功链接隔离的 20,000 行 DB/WAL/wrong-key 探针。**探针未实际运行**，其 20,000 行逻辑不是容量验收数据；源码重建、完整许可、WAL/temp 明文、full-disk/kill/key-loss/v5→v6 仍未验证。AAR 的 `minCompileSdk=37` 是实际包元数据，产品依赖/SDK 未改变。

追加源码审计固定了 core `63697beb...` 与 provider `476a9579...`，取得15份文件的原始摘要和顶层许可条款；Android 标签内较旧 core gitlink 的差异见 CT0-C13 和 [source audit](../../../contracts/spikes/sync_v1/encryption_source_audit.json)。这不是完整逐文件许可批准，也不是 AAR 可重现构建证据。

可复现命令、原始分类结果和限制见 [spike README](../../../contracts/spikes/sync_v1/README.md)。原探针断连后可能残留 `/data/local/tmp/excellent-calendar-sync-ct0-arm64-v8a` 单个测试可执行文件；不含用户数据。重连后只清理该精确路径，不卸载或清空用户 App。
