# 用户认证与个人信息模块 — 前端 AI 任务清单（flutter_client 本地）

> 状态：主体实现完成，2026-08-28 归档。该状态表示本计划代码与开发验证已完成；Backend API 和四个 `auth.refresh_token.*` MethodChannel 的机器 Contract 仍为 `planned`，不代表账号能力已正式激活。
>
> 面向：负责本地开发的前端 AI，工作范围为 `flutter_client/`（Dart + `android/` 内 Kotlin）。
>
> 对应后端清单：[认证与个人信息-01-后端CloudBackend.md](./认证与个人信息-01-后端CloudBackend.md)

> 并与后端清单保持阶段级对应。

## 1. 任务定位

在 `flutter_client/` 中实现用户认证与个人信息模块的完整本地闭环，支撑 12 项业务能力：
注册、邮箱验证、登录、会话自动恢复、查看个人信息、修改资料、修改邮箱、修改密码、
忘记密码重置、主动退出、Access Token 过期自动刷新、Refresh Token 失效自动回登录页。

职责划分（遵循需求书与 `contracts/README.md` 的 Authentication Boundaries）：

- Flutter 负责：页面、表单校验、网络请求（直连后端，不经过 Kotlin/C++）、登录状态管理、
  Access Token 内存管理、统一刷新流程、错误转换、用户资料缓存。
- Android Native（`flutter_client/android` Kotlin）**只负责**：Refresh Token 的安全保存/
  读取/删除/存在性查询（Android Keystore），通过 4 个 MethodChannel 调用暴露，不做任何登录业务判断。

C++ Core 不参与认证流程。

## 2. 硬性边界（不可违反）

1. **只允许修改 `flutter_client/**`**（Dart 与 `android/` 内 Kotlin）。`contracts/`、
   `docs/domains/`、`cloud_backend/`、`cpp_core/` 等均为只读。
2. **协议缺口必须停手上报**：发现 `contracts/` 与领域文档、本清单需求不一致，或缺少
   schema / 错误码 / MethodChannel 声明时，停止该切片并上报人工修订协议，**禁止临时发明**
   未声明的字段或方法。协议状态（`planned → integrated/active`）由用户统一切换，
   前端 AI 不得自行修改 `contracts/`。
3. **新增第三方依赖仅限 `dio`**（用户已确认）；不得升级或新增其他依赖、SDK、构建组件。
4. 邮件链接深链本阶段不实现：邮箱验证与密码重置只走 6 位验证码；Android App Links 后置。
5. 默认不自动进入离线模式：启动时认证恢复失败显示恢复失败页并提供重试。

## 5. 全局实现约束（安全与正确性）

- **分层**：沿用现有模式 `presentation → application（Controller/UseCase）→ gateway_interfaces
  → boundary_adapters（dio API client / MethodChannel adapter）→ native_contract DTO`；
  经 `main.dart` 组合根注入，原始 `Map` 只停留在适配层。
- **Token 边界**（对齐领域文档已确认决策）：
  - Access Token 只保存在 Flutter 内存（认证会话控制器），不写 SharedPreferences/文件/SQLite；
  - Refresh Token 长期只存在 Android Keystore 安全存储；Flutter 仅在刷新/退出请求期间通过
    MethodChannel 短暂读取使用，用后不保留在状态对象中；不落普通缓存、不写日志；
  - 页面/Widget 不得直接读取或拼接 Token；不得自行决定刷新时机；
  - 退出、刷新失败、密码重置完成后必须删除本地 Refresh Token。
- **统一网络层（dio）**：统一 baseUrl/超时/拦截器；自动附加 `Authorization: Bearer`；
  收到 Access Token 失效错误后触发**单飞刷新**：并发请求只允许一次刷新，其余请求等待
  同一结果；刷新成功后统一重试原请求一次；重试后仍失败不再二次刷新，清除登录状态并回登录页；
  禁止无限刷新/无限重试循环。
- **错误转换**：网络断开、超时、DNS 等 transport 失败与后端 `ApiError` 分开处理；
  建立「错误码 → 用户可读文案」映射表；`api_field_error` 显示到对应输入框附近；
  不向用户展示服务端堆栈或原始异常。
- **页面状态**：使用明确互斥的流程状态（initial/editing/submitting/success/form_error/
  network_error/server_error/auth_expired），禁止多个布尔变量组合表达状态；
  提交中禁用重复提交并显示加载反馈；页面销毁后不得更新页面状态；防重复提交保证
  不产生重复账号/重复邮件。
- **表单校验**：仅用于改善体验，不能替代服务端校验；登录失败保留邮箱输入、清空密码、
  不保存密码；注册/改邮箱失败保留用户已填内容。
- **用户资料缓存**：内存缓存 + 普通本地缓存两层；本地缓存按
  `cached_current_user.schema.json`（`storage_format_version=1`）写入 SharedPreferences，
  只含公开资料，禁止凭证字段；损坏缓存视为无缓存，不得崩溃。
- **Android 安全存储**：Keystore 主密钥 + AES-GCM 加密的令牌文件（应用私有目录，
  随应用数据清除而消失）；不得把 Refresh Token 写入普通 SharedPreferences；
  4 个 MethodChannel 严格按 schema 校验参数与 `NativeResult` v2 信封返回；
  Kotlin 不保存一份与后端竞争的会话真相源，只做存取删查。
- **忘记密码文案**：无论邮箱是否存在，统一显示“如果该邮箱已注册，系统会发送密码重置邮件”。
- **邮箱展示**：验证页等场景邮箱建议脱敏显示。
- **幂等**：注册、验证码重发、改邮箱申请、头像上传按后端要求携带 `Idempotency-Key`；
  客户端生成稳定 key，同一操作重试时保持 key 一致。
- **头像**：相册选择取消无副作用；校验可读性/格式/大小；正方形裁剪 + 合理压缩 + 上传前预览；
  上传显示进度；成功后以服务端返回为准更新状态与缓存并清理旧头像缓存；失败保留旧头像、
  可重新上传；删除头像需二次确认，成功后恢复客户端默认头像（`avatar_asset_id=null` 语义）。
- **导航**：扩展 `lib/app/routing/app_router.dart`；启动先经过统一认证检查页；
  退出登录后清空导航栈回登录页，按返回键不可回已登录页面。
- **修改密码/修改邮箱成功后**：后端会返回新 `AuthenticationResponse`
  （契约 `session_policy` 已锁定），前端必须保存新 Token Pair（新 Refresh Token 写回 Android），
  当前设备保持登录。

## 6. 分阶段任务清单

### 阶段 0：前置核对（无业务代码）

- 走查 `backend_api.yaml` 17 个端点（含 `auth.registration.email.update` 的密码所有权证明，
  以及 `AUTH_EMAIL_UNVERIFIED` 必带非空 `context.verification_challenge` 的 Schema 不变量）与
  `auth/`、`user/` schema、`method_channels.yaml` 的
  `auth.refresh_token.*` 四方法、`error_codes.yaml`、`cached_current_user` 缓存格式，
  与需求书及领域文档核对页面字段、错误分支、Token 边界是否一致。
- 缺口、冲突整理成清单**上报用户**，等待协议修订；未解决前不写对应切片。
- 与后端 AI 对齐联调地址、dev 邮箱查看方式（见后端清单阶段 0 输出）。
- 验收：`flutter test` 与 `flutter analyze` 基线通过。

### 阶段 1：认证基础设施（对应后端阶段 1）

- `native_contract`：为 auth/user/common schema 建立 Dart typed DTO（登录/注册/验证/
  token pair/current_user/api_result/api_error 等，字段 `snake_case`）。
- 新增 `dio` 依赖；`boundary_adapters` 实现统一 API client：baseUrl/超时/拦截器、
  `ApiResult` 解析、错误映射器、`Idempotency-Key` 支持。
- `gateway_interfaces` + `data`：`AuthGateway`、`UserGateway`、`RefreshTokenSecureStoreGateway`
  接口及其 dio / MethodChannel 实现。
- `application`：
  - 认证会话控制器：Access Token 仅内存、认证状态机（unknown/unauthenticated/authenticated）、
    当前用户内存缓存；
  - Token 刷新协调器：单飞互斥刷新队列、成功后重试原请求、失败统一清态回登录页；
  - 启动认证检查 UseCase：无 Refresh Token → 登录页；有 → 读 RT 调 `auth.token.refresh` →
    成功：更新内存 AT、新 RT 写回 Android、拉取 `user.get_current`、进主页；失败：删除 RT、
    清态、进登录页；网络不可用：恢复失败页 + 重试按钮；
  - 退出服务：尽力调用后端 `auth.logout`（临时读取 RT 携带），无论成败本地清 AT、清用户状态、
    清普通缓存敏感会话信息、删 Android RT、清导航栈。
- Android Kotlin：`bridge/channel` 注册 `auth.refresh_token.store/read/delete/exists`
  四个 handler；实现 Keystore 安全存储（AES-GCM 加密文件 + 原子写）；严格 schema 校验；
  `sensitive_payload` 处理（不写日志）。
- 组合根：`main.dart` / `ExcellentCalendarApp` 注入认证依赖；路由接入认证检查页作为启动入口。
- 验收（可用 Fake 后端/dio 桩驱动）：
  - 四方法存取删查正常，Kotlin 单测覆盖，真机可验证 Keystore 实际读写；
  - 启动检查四分支（无 RT/刷新成功/刷新失败/断网）正确路由；
  - 并发 N 个 401 只触发一次刷新、其余复用结果；刷新失败统一清态；
  - Access Token 不落盘；Refresh Token 不出现在日志与普通缓存。

### 阶段 2：登录注册（对应后端阶段 1）

页面：登录页、注册页、邮箱验证页（脱敏邮箱、验证码输入、确认验证、重发 + 60 秒倒计时、
修改邮箱入口、返回登录）。

- 登录：邮箱 + 密码 + 密码显隐；本地校验（邮箱格式/密码非空）；提交防重复；
  成功 → 保存 Token Pair（AT 内存、RT 写 Android）、更新全局登录态、缓存用户资料、进主页；
  失败分支：密码错、邮箱未验证（保留邮箱 → 跳验证页；后端保证携带非空
  `context.verification_challenge`，以其中的 `challenge_id`/`account_id`/掩码邮箱初始化验证页）、
  账号禁用、限流、断网、超时、服务器异常；
  错误提示可读，不展示堆栈。
- 注册：邮箱/用户名/昵称/密码/确认密码/密码显隐/同意协议（占位）/注册按钮；
  本地校验（必填、邮箱格式、用户名 `[a-z0-9_]{3,24}`、昵称长度、密码 ≥ 8 字符、
  两次一致、已勾选协议）；邮箱/用户名已存在 → 错误显示在对应输入框附近并保留其他内容；
  成功 → 跳邮箱验证页（不直接进主页）。
- 邮箱验证：验证码非空/长度校验；成功 → 后端返回 Token Pair → 按阶段 1 保存并拉取用户资料进主页；
  失败分支：错码/过期/已用/请求过多；重发：倒计时结束后可点、请求中禁止重复发送、
  成功后重新倒计时。
- 修改邮箱入口：输入新邮箱 + 注册时设置的密码，调用 `auth.registration.email.update`（携带
  `Idempotency-Key`）；成功 → 以返回的新 `RegistrationPendingResponse` 刷新验证页状态
  （新验证码发往新邮箱）并重新倒计时；失败分支：密码错（`AUTH_CURRENT_PASSWORD_INVALID`）、
  新邮箱已存在、账号已验证/不存在、限流，保留用户已填内容。
- 验收：验收流程一（注册）、流程二（登录恢复）本地部分；各失败分支、加载态、
  防重复提交、页面销毁不更新状态。

### 阶段 3：密码功能（对应后端阶段 2）

页面：忘记密码页、重置密码页、账号安全页之修改密码页。

- 忘记密码：邮箱输入 + 格式校验 + 发送按钮；成功后统一文案 + 垃圾邮件提示 + 重发倒计时 +
  返回登录；请求中禁止重复发送。
- 重置密码：验证码 + 新密码 + 确认新密码 + 密码显隐；本地校验；成功 → 清 AT、删除 Android RT、
  跳登录页并提示用新密码重新登录；失败分支：验证码错/过期/已用、新密码不合要求、请求过多。
- 修改密码（已登录）：当前密码 + 新密码 + 确认新密码；成功 → 保存后端返回的新 Token Pair
  （AT 内存、新 RT 写回 Android），当前设备保持登录；失败分支：当前密码错、新密码不合要求、
  新旧相同、会话失效（→ 清态回登录页）、网络异常。
- 验收：验收流程五、六本地部分；所有失败分支；凭证清理逻辑正确。

### 阶段 4：个人资料（对应后端阶段 3）

页面：个人信息主页、编辑资料页、修改邮箱页、账号安全页（修改密码入口、修改邮箱入口、
退出当前设备、退出所有设备）。

- 个人信息主页：展示头像/昵称/用户名/登录邮箱/邮箱验证状态/语言/时区；先读缓存立即展示，
  同时请求 `user.get_current`；成功更新页面、状态与缓存；失败且有缓存 → 显示“信息可能不是最新”
  + 重新加载按钮；无缓存 → 完整错误态 + 重试。
- 编辑资料：昵称/用户名/语言/时区等非安全字段；页面用当前资料初始化；无变化时保存禁用；
  提交成功以服务端返回的完整资料为准更新状态与缓存并返回主页提示成功；失败保留输入、
  可再次提交；不支持在普通编辑页修改登录邮箱/密码。
- 修改邮箱：当前邮箱只读 + 新邮箱 + 当前密码 + 发送验证邮件按钮；成功后跳邮箱验证页，
  完成验证后刷新资料并保存后端返回的新 Token Pair；新邮箱验证完成前页面不得显示已生效。
- 退出登录：确认对话框 → 尽力调 `auth.logout` → 无论成败本地清 AT/用户状态/敏感缓存/
  删 Android RT → 清空导航栈 → 登录页；返回键不可回已登录页。
- 退出所有设备：二次确认 → `auth.logout_all` → 本地同退出登录清理 → 登录页。
- 验收：验收流程三、九本地部分；缓存 v1 读写与损坏处理；退出清理完整。

### 阶段 5：头像（对应后端阶段 4）

- 图片选择（系统相册）：取消 → 无副作用、不报错、不修改头像。
- 图片处理：可读性/格式/大小校验、正方形裁剪、合理压缩、上传前预览。
- 上传：multipart（`part=file`）+ 进度展示 + `Idempotency-Key`；成功 → 更新用户状态、
  清理旧头像缓存、显示新头像、更新本地用户缓存；失败 → 保留旧头像、显示原因、可重新上传。
- 删除头像：确认对话框 → 调 `user.avatar.delete` → 成功后恢复默认头像。
- 验收：验收流程四本地部分；失败分支；重启后头像仍正确。

### 阶段 6：完善与测试（对应后端阶段 5）

  登录失效统一处理、用户资料更新以服务端为准。
- 测试：Controller/刷新协调器/错误映射/DTO 单元测试；各页面状态与表单 Widget 测试；
